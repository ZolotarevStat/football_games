# 7-40 Parser Pipeline

## Назначение

Пайплайн собирает статистику по игре 7-40 из локальных Telegram-экспортов и разделен на два явных слоя:

- `PublicBlogStatsParser` - публичный блог/канал: контексты МДП, OCR составов, сыгравшие варианты, статистика команд и турниров;
- `TeamPreviewParser` - командный чат: тренерские превью, рекомендации вариантов, линии игроков команды.

Пайплайн:

- распознает скриншоты составов команд из Excel-таблиц;
- парсит выбранные игроками варианты;
- извлекает сыгравшие варианты из верхней 4x10 шапки итоговых скриншотов и текстовых блоков `Сыграли варианты`;
- строит распределения по вариантам, категориям, турнирам, командам и матчам;
- генерирует Excel/CSV/Markdown/HTML-отчеты и визуализации;
- сохраняет корпус командных превью для следующей итерации генерации шаблонов.

Raw Telegram exports и generated output остаются локальными и не коммитятся.

## Входы

По умолчанию скрипт ожидает экспорты Telegram:

- публичный канал: `~/Downloads/Telegram Desktop/ChatExport_2026-04-26`
- командный чат: `~/Downloads/Telegram Desktop/ChatExport_2026-04-26 (2)`

Оба каталога должны содержать `result.json`; публичный экспорт также должен содержать `photos/`.

```bash

python scripts/analyze_7_40.py \
  --days 14 \
  --out-dir output/7_40_analysis
```

- `hits_overall.csv` - распределение сыгравших вариантов в целом;

Ограничение полного прогона: старые форматы скриншотов и часть старых алиасов команд дают заметный `unknown*`. Общие распределения и разрезы по турнирам используют все распарсенные варианты, а team-level визуализации и `picks_by_team.csv` строятся только по строкам с распознанной командой.

Чтобы не гонять полный OCR-цикл на каждой итерации, запускай полный прогон с `--backup-results`: локальный zip результата сохраняется в `output/7_40_analysis/backups/`. Git его не отслеживает.

## Как устроен парсер

Для скриншотов составов:

- команды читаются из синих header-блоков таблицы;
- строки ставок читаются через `pytesseract.image_to_data`;
- склеенные OCR-цифры вида `11142934` разбираются динамическим парсером в 7 валидных вариантов;
- каждая строка привязывается к команде по вертикальной секции таблицы;
- качество проверяется через ожидаемые 16 команд, 16x5 строк игроков и 16x5x7 вариантов.

Для итогов:

- основной источник сыгравших вариантов - верхняя 4x10 grid-шапка итогового изображения;
- дополнительный источник - текстовые сообщения вида `Сыграли варианты: ...`;
- дубли между image/text-источниками убираются по матчу, дате и набору сыгравших вариантов;
- полный OCR итоговых таблиц не запускается в основном пайплайне, чтобы не замедлять итерации.

Для превью команды:

- старт превью определяется по `Следующий МДП`, `Стартовый МДП`, `МДП:` и `Предматчевая статистика`;
- если превью разбито на несколько сообщений, соседние блоки склеиваются в один `preview_id`;
- извлекаются `recommended_variants`, коэффициенты, предполагаемые счета, дедлайн, прошлый результат, судья, заметки по карточкам, заменам и пенальти;
- полный текст сохраняется в `team_chat_previews.csv` и `team_preview_corpus.md`.

## Новые распределения и визуализации

Помимо базовых top-N графиков, HTML теперь включает:

- частоту всех 40 вариантов в grid-формате;
- bar chart всех 40 вариантов без отсечения top-N;
- распределение сыгравших по всем 40 вариантам;
- частоту рекомендаций в командных превью;
- сравнение категорий: ставки команд vs сыгравшие vs рекомендации;
- объем распарсенных событий по турнирам;
- профили вариантов по турнирам и командам;
- структуру ставок по категориям;
- концентрацию top-3 вариантов по командам;
- эффективное число вариантов по командам;
- кривую концентрации выбора вариантов;
- качество разметки по МДП.

Ключевые новые CSV:

- `public_blog_*` - промежуточные таблицы публичного парсера;
- `team_chat_*` - промежуточные таблицы командного парсера;
- `preview_recommendations_overall.csv`;
- `preview_recommendations_by_competition.csv`;
- `picks_by_category.csv`, `hits_by_category.csv`;
- `picks_by_match.csv`, `hits_by_match.csv`;
- `team_preview_corpus.md`.
- `unknown_screenshot_files.csv` - агрегированный список скриншотов с `unknown*` или неполными строками;
- `unknown_screenshot_rows.csv` - проблемные строки OCR;
- `unknown_screenshot_photo_list.txt` - plain-text список абсолютных путей к скриншотам для точечного перепрогона.

## Следующие шаги

- Снизить `unknown*` на полном датасете: добавить алиасы старых команд и отдельные правила для старых форматов скриншотов.
- Дочистить `Не определено` по турнирам для старых МДП, где в тексте нет явного чемпионата.
- Добавить больше визуализаций и распределений поверх уже собранного full dataset.
- Добавить в превью паттерны замен команд, манеры судьи с желтыми, красными и пенальти.
- Подумать о возможности автоматизации части процессов в блоге за счет получившегося фреймворка.
