# 7-40 Parser Pipeline

## Назначение

Пайплайн собирает статистику по игре 7-40 из локальных Telegram-экспортов:

- распознает скриншоты составов команд из Excel-таблиц;
- парсит выбранные игроками варианты;
- извлекает сыгравшие варианты из верхней 4x10 шапки итоговых скриншотов;
- строит распределения по вариантам, турнирам и командам;
- генерирует Excel/CSV/Markdown/HTML-отчеты и визуализации.

Raw Telegram exports и generated output остаются локальными и не коммитятся.

## Входы

По умолчанию скрипт ожидает экспорты Telegram:

- публичный канал: `~/Downloads/Telegram Desktop/ChatExport_2026-04-26`
- командный чат: `~/Downloads/Telegram Desktop/ChatExport_2026-04-26 (2)`

Оба каталога должны содержать `result.json`; публичный экспорт также должен содержать `photos/`.

## Установка

Python-зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Системная зависимость для OCR:

```bash
brew install tesseract
brew install tesseract-lang
```

## Быстрый прогон на последних 14 днях

```bash
MPLCONFIGDIR=output/7_40_analysis/.mpl \
python scripts/analyze_7_40.py \
  --days 14 \
  --out-dir output/7_40_analysis
```

Результаты будут в `output/7_40_analysis/last_14_days/`.

Ключевые файлы:

- `summary.xlsx` - основной Excel-отчет;
- `report.md` - краткий Markdown-отчет;
- `visualizations/index.html` - HTML-индекс визуализаций;
- `lineup_quality_by_match.csv` - контроль качества OCR по МДП;
- `picks_overall.csv` - распределение выбранных вариантов в целом;
- `picks_by_competition.csv` - распределение выбранных вариантов по турнирам;
- `picks_by_team.csv` - распределение выбранных вариантов по командам;
- `hits_overall.csv` - распределение сыгравших вариантов в целом;
- `hits_by_competition.csv` - распределение сыгравших вариантов по турнирам.

## Полный прогон

```bash
MPLCONFIGDIR=output/7_40_analysis/.mpl \
python scripts/analyze_7_40.py \
  --out-dir output/7_40_analysis_full
```

Если экспорты лежат в других каталогах:

```bash
MPLCONFIGDIR=output/7_40_analysis/.mpl \
python scripts/analyze_7_40.py \
  --public-export "/path/to/public/ChatExport" \
  --private-export "/path/to/private/ChatExport" \
  --out-dir output/7_40_analysis_full
```

## Текущее состояние алгоритма

На 14-дневном срезе от `2026-04-11 20:16:38`:

- публичных сообщений в срезе: 77;
- сообщений командного чата в срезе: 83;
- распознано строк игроков: 398;
- распознано вариантов ставок: 2786;
- распознано итоговых шапок: 5;
- сыгравших вариантов из итоговых шапок: 59;
- `unknown*` по командам: 0;
- неполных строк игроков: 0.

Один МДП в срезе неполный по строкам состава: `Ноттингем Форест - Порту`, 78/80 строк. Это учитывается в `lineup_quality_by_match.csv` как `partial_roster`, а не смешивается с `unknown`.

## Как устроен парсер

Для скриншотов составов:

- команды читаются из синих header-блоков таблицы;
- строки ставок читаются через `pytesseract.image_to_data`;
- склеенные OCR-цифры вида `11142934` разбираются динамическим парсером в 7 валидных вариантов;
- каждая строка привязывается к команде по вертикальной секции таблицы;
- качество проверяется через ожидаемые 16 команд, 16x5 строк игроков и 16x5x7 вариантов.

Для итогов:

- основной источник сыгравших вариантов - верхняя 4x10 grid-шапка итогового изображения;
- полный OCR итоговых таблиц не запускается в основном пайплайне, чтобы не замедлять итерации.
