# MVP Finish Plan

Дата обновления: 2026-06-11.

## Текущее решение

Продовый MVP работает в режиме polling-worker на Yandex Cloud Compute VM:

```text
Telegram Bot API getUpdates -> YC Compute VM systemd worker -> Google Sheets
```

Webhook отключен. Это осознанный MVP-выбор после нестабильных timeout на связке Telegram -> Yandex Cloud Functions и исходящих вызовах Cloud Functions к `api.telegram.org`.

Текущий статус:

- Runtime: YC Compute VM.
- Service: `wc-predictions-bot`, `systemd`, enabled + active.
- Durable state: Google Sheets.
- Локальный ноутбук не является production runtime.
- Cloud Functions/API Gateway оставлены как артефакты эксперимента, но не являются текущим runtime.

## Что уже входит в MVP

### Игрок

- Привязка участника по invite/PIN через `/start`.
- Тестовый доступ по списку `ALLOWED_USERNAMES`, если включен `OPEN_REGISTRATION_ENABLED=true`.
- Приватный ввод прогнозов в личке боту.
- Мини-дашборд после `/start`, сохранения, `/submit`, `/authors` и `/cancel`.
- Интерактивный сценарий `/predict`: матч -> 7 счетов -> автор команды 1 -> автор команды 2 -> подтверждение.
- В `/predict` показываются ближайшие релевантные матчи, а не весь календарь:
  - максимум из 5 ближайших матчей;
  - матчи 3 ближайших игровых дней;
  - кнопка "Все матчи ближайшего тура".
- При выборе матча бот показывает пару команд и дедлайн.
- При выборе авторов бот показывает топ-5 доступных кандидатов и кнопку "Показать полный список".
- Игроки, уже выбранные участником в других актуальных прогнозах, скрываются и явно перечисляются в подсказке.
- Кнопка `Назад` удаляет активное inline-окно или сбрасывает текущий черновик на подтверждении.
- Быстрая команда `/submit MATCH_ID scores | Автор1 | Автор2`.
- Быстрая команда `/authors MATCH_ID | Автор1 | Автор2` для замены только авторов до дедлайна.
- Компактный список ближайших открытых матчей через `/matches`.
- Подробные правила через `/rules`.
- Просмотр своих прогнозов через `/my` с визуальным отображением матча и счетов.

### Валидация

- Server-side deadline: новые прогнозы и правки после дедлайна блокируются.
- Server-side проверка 7 уникальных счетов.
- Server-side проверка авторов из активной заявки команды.
- Подсказки по ближайшим игрокам из заявки при ручной ошибке в `/submit` и `/authors`.
- Запрет повтора авторов Г+П внутри одного прогноза.
- Запрет повторного автора в актуальных прогнозах участника.
- Отменённые матчи и технические результаты не учитываются в scoring.

### Админ

- `/admin` показывает справочник админских команд.
- `/status MATCH_ID` показывает, кто сдал прогноз по матчу.
- `/publish MATCH_ID` публикует прогнозы после дедлайна в турнирный чат.
- `/score MATCH_ID` и `/score all` пересчитывают очки по заполненным результатам.
- `/leaderboard` отправляет таблицу лидеров в турнирный чат.
- Ежедневные уведомления в 12:00 МСК для участников, которые уже отправляли хотя бы один прогноз.
- Результаты матчей для MVP заносятся вручную в Google Sheets.

## Работа в группе участников

Основное правило: прогнозы не принимаются в группе, только в личке боту.

Режим Telegram:

- У BotFather желательно оставить `Privacy Mode = ENABLED`.
- Тогда бот в группе видит только команды, ответы на свои сообщения и упоминания, а не весь поток чата.

Кодовая защита:

- В группах обычный текст игнорируется.
- В группах прогнозные команды `/start`, `/predict`, `/submit`, `/authors`, `/my`, `/cancel` не выполняются; бот отвечает коротким сообщением, что прогнозы принимаются в личке.
- В группах разрешены только явные команды из allowlist: `/help`, `/rules`, `/matches`, `/status`, `/publish`, `/score`, `/leaderboard`, `/admin`, а также forecast-команды только как redirect в личку.
- Команды с упоминанием бота нормализуются: `/my@tii_wc_predictions_2026_bot` работает так же, как `/my`.

Практика для участников:

- В общем чате закрепить инструкцию: "Прогнозы отправлять в личку @tii_wc_predictions_2026_bot. В группе бот нужен только для публикации закрытых прогнозов и таблицы".
- Организаторы используют `/publish MATCH_ID` после дедлайна и `/leaderboard` после обновления результатов.

## Что осталось сделать

### P0 - перед боевым стартом

1. Провести live smoke на одном ближайшем матче:
   - игрок открывает `/start`;
   - делает прогноз через `/predict`;
   - проверяет `/my`;
   - меняет авторов через `/authors`;
   - после дедлайна админ проверяет `/status MATCH_ID`;
   - админ публикует прогнозы через `/publish MATCH_ID`.
2. Проверить live-данные по первым матчам после каждого импорта:
   - `kickoff_msk`;
   - `deadline_msk = kickoff_msk - 5 минут`;
   - человекочитаемые `match_id`;
   - заявки и сортировка игроков по priority.
3. Финализировать режим доступа:
   - для открытого теста можно оставить `OPEN_REGISTRATION_ENABLED=true`;
   - перед закрытым боевым запуском включить allowlist / invite/PIN и проверить, что `/status MATCH_ID` считает ожидаемых участников корректно.
4. Проверить, что `TOURNAMENT_CHAT_ID` указывает на правильный общий чат.
5. Смерджить актуальный GitHub PR после финального просмотра.

### P1 - эксплуатация организатора

1. Обновить инструкцию организатора:
   - куда и в каком формате заносить результаты в Google Sheets;
   - как писать авторов голов/пасов по неймингу из заявки;
   - как запускать `/score`, `/leaderboard`, `/publish`.
2. Добавить `/remind MATCH_ID` или зафиксировать ручной флоу напоминаний по выводу `/status MATCH_ID`.
3. Сделать короткий runbook эксплуатации YC worker:
   - проверить статус сервиса;
   - посмотреть последние логи;
   - перезапустить сервис;
   - раскатить новую версию.
4. Настроить минимальный health-check:
   - ручной чек перед игровым днем уже достаточен для MVP;
   - cron/automation можно добавить, если тестирование покажет сбои.
5. Проверить daily notifications на реальном игровом дне:
   - не дублятся;
   - приходят только участникам с хотя бы одним прогнозом;
   - текст содержит матчи ближайших 24 часов.

### P2 - после стабильного теста

1. Улучшить админский флоу результатов через бота, только если редактирование Google Sheets окажется неудобным:
   - выбрать матч;
   - ввести счет;
   - выбрать/ввести авторов голов и ассистов;
   - запустить scoring.
2. Улучшить визуал таблицы лидеров:
   - компактная красивая таблица после игрового дня;
   - понятные tie-breaker поля.
3. Добавить more detailed audit:
   - кто и когда менял прогноз;
   - какие прогнозы были перезаписаны;
   - какие прогнозы заблокированы дедлайном.
4. Перенести секреты с VM filesystem в более аккуратный механизм, если VM останется runtime дольше MVP:
   - минимум `chmod 600`;
   - лучше Lockbox + deploy script.
5. Убрать/архивировать Cloud Functions как не-prod путь, чтобы не путать эксплуатацию.

## Stop-rules

- Не расширять MVP до веб-интерфейса.
- Не добавлять базу данных, пока Google Sheets хватает.
- Не делать сложную авторизацию: invite/PIN + telegram_id достаточно для MVP.
- Не возвращаться к webhook, пока polling worker стабилен и работает на YC.
- Не делать админский ввод результатов в боте, если Google Sheets остается быстрее и надежнее для организатора.
